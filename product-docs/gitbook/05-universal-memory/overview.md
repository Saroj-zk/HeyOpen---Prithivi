# Universal Memory explained

Universal Memory is HeyOpen's cross-model context feature. It is designed to keep useful details such as preferences, projects, decisions, and constraints available when you work with different supported AI models.

## Why it matters

Without memory, you may need to repeat your preferences and project history whenever you change models or start a new conversation. Universal Memory creates a separate context layer intended to reduce that repetition.

## Examples of what to remember

- **Preferences:** "I prefer concise answers with clear headings."
- **Project context:** "My current app uses PostgreSQL and TypeScript."
- **Important constraints:** "The interface must support keyboard navigation."
- **Decisions:** "We selected the second visual direction for the product launch."

## Where memory lives

The public Universal Memory page describes memory as **encrypted and stored in the current browser**, not automatically synced across devices. Clearing browser site data can remove it. The legal Privacy Policy is more general and notes that storage arrangements can differ by implementation, so rely on the controls visible in your session.

## Control and sharing

The memory settings illustration shows separate controls for using memory, automatically creating memories, and sharing saved context with external models. External-model sharing is described as **off by default**.

## Memory does not guarantee correctness

A remembered detail may become outdated, and different models can use the same context differently. Review saved entries, remove outdated information, and validate important outputs.
